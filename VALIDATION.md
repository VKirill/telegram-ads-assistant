# Валидация 0.4.0

## Что проверяется до заполнения

`validate_package` возвращает valid, errors (для человека), issues (структурированные записи), serverValidationRequired. Формат issue: field, code, message, actual, limit, source. Отсутствующий actual/limit не выдаётся за ноль.

Проверки: структура пакета и объявлений, ID и дубли, неизвестные поля объявления, статус, бюджет и общий cap, CPM/дневной бюджет с двумя знаками, viewsPerUser, boolean picture, типы списков, дубли/конфликты включения и исключения, допустимые поля каждого target, совместимость медиа и placement, URL бота и параметры, Search без start, текст/переносы/ссылки. Счётчик custom emoji повторяет getAdTextLength официального клиента.

Текущий снимок кабинета от 14.09.2026: textMaxLength=160, channelItemsLimit=100, botItemsLimit=100, searchQueryItemsLimit=10, mediaPhotoSizeLimit=5242880, mediaVideoSizeLimit=20971520. Источник: read_constraints, фиксированный allowlist параметров текущего кабинета. При подготовке через MCP эти значения перечитываются. Офлайн проверка использует датированный снимок, не гарантирует неизменность кабинета.

Для стран/языков/тем неизвестен отдельный опубликованный предел. В приложении остаётся технический cap 100 элементов, это не установленное правило Telegram. Выбор проверяется через сам кабинет. Числовые min/max и maxlength HTML-полей применяются при заполнении.

## Медиа

Расширение проверяет тип, размер, возможность декодирования Chrome, положительное разрешение, конечную положительную длительность видео. После загрузки требуется новый серверный media handle. Возвращаются width, height, duration, aspectRatio. Без успешного декодирования загрузка не начинается.

Сигнатура файла в Node — предварительная проверка, не полная декодировка. Минимальное/максимальное разрешение, пропорции, продолжительность и конкретные кодеки не объявляются правилами Telegram без достоверного источника. Успех Chrome metadata не означает прохождение серверной проверки или модерации.

## Что решает только Telegram

Доступность и допустимость канала/бота, порог активной аудитории, допустимость назначения, профиль и работоспособность бота, географические ограничения кабинета, текущий минимум CPM и надбавки, достаточность баланса, корректность содержимого и модерация. Ошибки видимых полей возвращаются как ошибки, не как успешная запись. При неопределённом исходе требуется чтение кабинета, а не повтор commit.

Ни `valid:true`, ни `media_uploaded` не означают одобрение модерации. Полное воспроизведение закрытой серверной валидации Telegram не заявляется.

Источники: https://ads.telegram.org/guidelines ; https://telegram.org/js/promote.js?112 ; live read_constraints 14.09.2026. Контентные правила проверяет человек/агент с источниками, не примитивный стоп-словарь.
