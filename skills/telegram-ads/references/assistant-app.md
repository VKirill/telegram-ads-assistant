# Работа через Telegram Ads Assistant

Это исполнительный слой той же системы `telegram-ads`, не отдельный продукт. Методика определяет гипотезы и решения; приложение заполняет и читает кабинет. Оно не ищет релевантные каналы, не измеряет пересечения и не заменяет аналитику качества лидов.

## Выбери инструмент автоматически

Выполняй эту проверку, когда нужен доступ к кабинету, даже если пользователь не упомянул приложение. Для работы только с предоставленной выгрузкой или медиапланом Chrome не открывай.

1. Определи рабочую машину и Chrome-профиль с нужным Telegram Ads аккаунтом. Используй доступный инструмент инвентаризации браузера, не предполагай, что профиль на другой машине совпадает.
2. Проверь доступные подключения MCP Assistant и открытые вкладки. Известный адрес приложения: `chrome-extension://femelgagbpmggedhendamamfjfkljegi/index.html`. Если вкладки нет, проверь список расширений нужного профиля через интерфейс Chrome; отсутствие открытой панели или MCP-инструмента само по себе не означает отсутствие установки. Для другой сборки сопоставь название Telegram Ads Assistant с её фактическим ID.
3. Если расширение установлено и включено, открой его панель и проверь `extension_status` через доступное подключение. При рабочем мосте используй MCP для поддерживаемых операций. Отдельный скилл приложения больше не нужен: команды ниже — часть `telegram-ads`.
4. Если расширение есть, а связи нет, проверь открытую панель, состояние подключения и локальный сервис. При известной установке мост запускается командой `npm start` в её каталоге; MCP-клиент подключается к `node /ABSOLUTE/PATH/server/mcp.js`. Не выдумывай путь, команды инструментов или настройки. Если доступна операция через панель приложения, её можно выполнить посредством Computer Use.
5. Если приложения нет, используй Computer Use непосредственно в Telegram Ads. Если приложение установлено, но подключение восстановить не удалось или нужная операция им не поддержана, также переходи к Computer Use, указав причину. Не устанавливай приложение и не меняй профиль только ради продолжения задачи.
6. Если наличие приложения или нужный профиль проверить невозможно, обозначь это как неизвестное. При доступном интерфейсе правильного кабинета продолжай через Computer Use; если недоступен и кабинет, подготовь доступную часть плана и сообщи конкретное препятствие.

При использовании Assistant сравни версию из `extension_status` и доступные схемы команд с контрактом 0.5.0 ниже. При несовпадении проверь изменившиеся параметры в документации установленного приложения. [Репозиторий системы](https://github.com/VKirill/telegram-ads-assistant) ставит приложение и навык `telegram-ads` вместе.

При работе через MCP перед заполнением: `extension_status` → `capabilities` → `read_account` → `read_constraints`. Сверь выбранный аккаунт, валюту, существующие объявления и доступность нужного режима. Если чтение не даёт однозначного аккаунта/валюты, это неизвестные данные, а не основание подставить TON из примера. `read_account` возвращает загруженные строки, не гарантирует полный архив. Наличие команды в `capabilities` не означает, что операция выполнена: после каждого изменения сверяй фактический результат в кабинете.

Один оператор на кабинет/активный черновик. Не готовь два объявления параллельно: следующая подготовка может заменить форму и fingerprint предыдущей.

## Работай через Computer Use при отсутствии доступного Assistant

1. Открой правильный кабинет и прочитай аккаунт, валюту, режим, существующие объявления и ограничения формы. После перехода или действия обновляй состояние страницы перед следующим решением.
2. Подготовь одну строку плана в несохранённой форме. Сохрани статус On Hold; проверь URL, текст, медиа, выбранные каналы/страны, исключения, CPM и бюджет. Примени правила посадочной и географии из последнего раздела этого файла.
3. Перед сохранением сопоставь видимые значения с планом. Следуй действующим разрешениям на создание и расход, а также требованиям используемого Computer Use к подтверждению действий. Не отмечай соглашение автоматически без нужного разрешения.
4. После разрешённого сохранения найди объявление по уникальному названию, открой его и прочитай фактические настройки и ID. Сообщение об отправке не заменяет эту проверку. При неопределённом результате сначала ищи запись, не создавай повторно.
5. При чтении статистики зафиксируй период, валюту, активные фильтры и полноту таблицы. Недоступные значения оставляй неизвестными. Работай последовательно, без параллельных изменений одной формы.

Команды MCP, fingerprint и operationId относятся только к Assistant. При работе непосредственно в кабинете используй видимые поля, подтверждения и сохранённые ID; не сообщай о получении MCP-результатов, которых не было.

## Разложить методику на операции

| Этап методики | Что передать приложению | Что сохранить в проекте |
|---|---|---|
| Реестр каналов | Подтверждённые username и тип таргетинга; отбор выполняется до приложения | Причины включения, источник и дата, кластер |
| Тест креативов | По объявлению на вариант, одинаковый `target.channels` пул и остальные настройки | creative_id, local ad.id, URL/метка, лимит |
| Тест каналов 1к1 | По объявлению на канал: `target.channels` содержит ровно один username; креатив одинаковый | Связь test_id → channel → ad.id → externalId |
| Пересечения | Только обоснованные `excludeChannels` в правильном `target.type` | Кого исключаем и почему; неизвестное пересечение |
| Исполнение | validate → prepare → сверка → разрешённый commit → повторное чтение | fingerprint, operationId, receipt, подтверждённые поля |
| Анализ | `read_statistics`/`export_csv` для сохранённого numeric adId и месяца | Исходный экспорт, период/валюта, отдельные расчёты |
| Оптимизация | `prepare_edit`/`commit_edit` для CPM/статуса; бюджет отдельной парой | Причина, до/после, лимиты, результат проверки |

Для 1к1 создай отдельную запись пакета на каждый канал. До валидации подставь готовые URL и уникальные метки: Assistant не раскрывает макросы сторонних инструментов. Пул и 1к1 не означают дедупликацию людей.

## Составь пакет объявлений

См. [учебный JSON](../assets/assistant-package.example.json). Он локальный, не предназначен для отправки в кабинет. Заменяй все демонстрационные сущности и пересчитывай CPM/бюджет под реальный аккаунт.

- Верхний уровень: `version: 1`, уникальный `id`, `currency`, `totalBudget`, `ads` (1–100 записей).
- Валюта: `TON`, `EUR`, `XTR` (Stars). Перед заполнением приложение сверяет её с живым кабинетом; неизвестная валюта или несовпадение останавливают подготовку. Конвертации нет. Учебные суммы в евро не становятся бюджетом в Stars или TON.
- Объявление: `id`, `title`, `text`, `url`, `budget`, `cpm`, `status: "on_hold"`, `target`; дополнительные поля — только по текущей схеме. Сумма бюджетов ≤ `totalBudget`; общий лимит нескольких пакетов контролирует агент, локальный cap одного пакета его не заменяет.
- `id` пакета и объявления — локальные строковые ID. ID сохранённого объявления — числовой `externalId`/`adId`, полученный после чтения кабинета. Не передавай локальный slug в `read_ad`.
- Суммы CPM/проверяемых денежных полей — с точностью не более двух знаков, положительные где требует схема. Минимум CPM и надбавки проверяет живой кабинет.
- Посадочная: HTTPS-сайт с UTM, t.me канал, пост, invite или бот с необязательным start. Search требует простой t.me URL. Это синтаксическая поддержка: Telegram проверяет назначение в конкретном аккаунте. Для сайта подготовка ждёт нативное поле website_name; отказ прерывает операцию. Не обходи отказ заменой URL после проверки. `websiteName` — необязательная подпись сайта.
- Не подменяй посадку на канал ботом без решения владельца. После изменения URL снова проверяй фактическую форму и ошибки.
- `media` в пакете — только имя файла; это не загруженный ассет. Для передачи файла нужен отдельный `upload_media`.
- Изменённое содержимое staged-пакета требует нового package.id; тот же ID с другим hash отклоняется. Сохраняй связь версий в проекте.

## Выбери режим таргетинга и исключения

| target.type | Поля и смысл |
|---|---|
| `channels` | `channels`, `topics`, `languages`, `excludeChannels`, `excludeTopics`; исключаются места показа |
| `users` | `countries` обязательны; `languages`, `topics`, `channels`, `excludeChannels`, `excludeTopics`; исключаются аудитории |
| `search` | `queries`; простой URL бота без start, без загружаемого медиа |
| `bots` | `bots`; без произвольного медиавложения, доступность площадки проверяет Telegram |

Username без `@`; названия стран, языков и тематик — как в английском кабинете. Один и тот же канал нельзя поместить одновременно во включение и исключение одного объявления. Исключение собственного рекламируемого канала для новых подписчиков относится к **Users**, если оно доступно в выбранном сценарии. Не включай в каждую запись 1к1 все соседние каналы как исключения. `excludeChannels` — имя поля адаптера, не обещание анализа/устранения пересечений.

`placement: "video_banner"` у Users — размещение в чужом видео, не загрузка собственного MP4; обычный режим — `channel_post`. Не смешивать video_banner и загрузку своего медиа.

## Подготовить и сохранить по одному

1. Сверь финальный план и выполни `validate_package({package})`. `valid: true` — локальная проверка; `serverValidationRequired` остаётся отдельным фактом. Сопоставь пакет с текущими лимитами из `read_constraints`, затем проверь ошибки нативной формы: локальный валидатор не заменяет серверную проверку.
2. `stage_package({package})` сохраняет только локальные данные. Приёмка пакета не создаёт объявлений и не расходует рекламный бюджет.
3. `prepare_ad({ad, currency: package.currency})` заполняет один несохранённый черновик on_hold. Проверь реальные fields/targets/errors, посадку, валюту, CPM/надбавку и бюджет против строки плана. Ошибка поля — причина исправить план/ввод, не продолжить сохранение.
4. Если нужно медиа: `upload_media({path})` **или** `upload_media({url})`, ровно один источник. Path принадлежит host сервиса. URL должен отдавать файл, не страницу просмотра. Требуй `media_uploaded` и `mediaSaved: true`, а не только локальное превью. Для существующего объявления используется numeric `adId`. Консервативные пределы приложения: JPG/PNG до 5 MB, MP4 до 20 MB, кэш 200 MB; декодирование и серверная проверка отдельно.
5. `read_draft({})` возвращает свежий fingerprint. Сверь содержимое после медиа/ручных изменений; новый fingerprint нельзя принимать вслепую. Назначь стабильный `operationId` для одной конкретной попытки: 8–100 латинских букв, цифр, `_`/`-`.
6. В пределах уже полученного разрешения выполнить `commit_ad({operationId, expectedFingerprint})`. Команда автоматически отмечает принятие условий Telegram: соответствующее разрешение владельца должно быть установлено до вызова. Если его нет, подготовь всё выше и запроси только недостающее решение, пояснив причину из технического контракта. Не спрашивай повторно уже данное разрешение. Создание on_hold не равно активации, но уже создаёт серверную запись и назначает бюджет.
7. `submitted_needs_verification` — ещё не успех. `read_account` → найти ровно одну запись по уникальному title → `read_ad({adId})` и `read_budget({adId})`. Сверь текст, URL, target/исключения, CPM, медиа, статус, бюджет. Ноль или несколько совпадений — неопределённость; не выбирай случайное. Запиши подтверждённый externalId и результат сверки.
8. Активация, если поручена, — отдельное изменение статуса после проверки. После таймаута/обрыва сначала читай кабинет и проверяй receipt; не повторяй commit с новым operationId. Идемпотентность текущей установки не заменяет серверную сверку.

Не выводи ключи `.local/bridge.json` и `src/local-config.js`; не копируй их в пакеты. Не выставляй локальный мост 127.0.0.1:18791 в публичный интернет. Сбой связи: проверить отдельный `npm start`, нужный Chrome и открытую панель, затем `extension_status`. `reload_extension` использовать при необходимости обновления; `requested` не успех, нужен `reloadReceipt` и повторный статус.

## Изменения, статистика, ручная панель

- `prepare_edit({adId, patch})` → сверка fingerprint подготовленного изменения → `commit_edit({adId, operationId, expectedFingerprint})` → повторное чтение. Таргетинг сохранённого объявления неизменяем; новые каналы требуют нового объявления. `clone_ad` лишь открывает черновик копии.
- `prepare_budget({adId, direction: "add" | "withdraw", amount})` → проверка суммы/лимита и fingerprint → `commit_budget({adId, direction, operationId, expectedFingerprint})` → `read_budget`, история операции. Это операции бюджета объявления, не пополнение аккаунта и не подключение кошелька. Не повторять финансовую операцию при неопределённом исходе.
- Считай изменение CPM разовой операцией. Для автоматического повторения требуется отдельно настроенный процесс с расписанием и лимитами. Парные правила повышения и снижения CPM описаны в [тестировании и оптимизации](testing.md); они выполняются в инструменте с поддержкой автоправил или отдельном явно порученном процессе; не обещай мониторинг 24/7 из одного MCP-вызова.
- `read_statistics({adId, month: "YYYYMM"})` и `export_csv` — отображаемые данные/доступный CSV, не canvas-графики и не произвольный диапазон дат. Проверь выбранный месяц. Неполное чтение или недоступная метрика — unknown, не ноль.
- `delete_ad` только открывает подтверждение; окончательное удаление не реализовано. После подготовки расписания прочитай сохранённые часы и часовой пояс; только после совпадения с планом считай настройку завершённой. Открытие подтверждения удаления не означает удаление.
- В панели вкладка **«Кабинет» → «Обновить»** читает объявления; выбор строки и **«Действие»** дают чтение/подготовку полей. **«Пакеты» → «Импорт JSON»** загружает локальный пакет; **«Пример»** содержит фиктивные объявления. **«Журнал» → «Экспорт журнала»** — журнал действий, не финансовая отчётность. Импорт и кнопка подготовки не означают сохранение/публикацию; полный агентский путь выполняется MCP.

Заверши отчётом: account/валюта, package/test/local ID → externalId, операция и receipt, проверенные поля, статус модерации отдельно от активации, бюджет/расход, период статистики, неизвестное и следующий шаг. Для закрытой JSON-схемы сохраняй метаданные в отдельном соседнем файле по [правилам размещения результатов](agency.md); не добавляй произвольные поля в ad.

## Определи допустимую посадочную и географию

1. Прочитай валюту активного кабинета: `TON`, `EUR` или `XTR` (Stars). Сверь аккаунт с брифом. Не определяй тип кабинета по открытому разделу, например `/account/events`, и не подставляй валюту из учебного пакета.
2. Выбери режим таргетинга и введи целевой URL в несохранённый черновик. Для внешнего сайта дождись распознавания кабинетом и поля `website_name`. Сообщение `You can't promote external links` означает запрет внешней посадочной в выбранном кабинете/режиме: останови подготовку этой строки. Предложи подходящий кабинет либо Telegram-посадочную; не меняй воронку без решения владельца.
3. Не вводи общий запрет или разрешение сайтов для всех EUR, TON или Stars-кабинетов. Права зависят от аккаунта и способа доступа. Учитывай ответ текущей формы для конкретной ссылки; распознавание URL ещё не означает прохождение модерации.
4. Для геотаргетинга в Users выбери каждую нужную страну из `Target countries`. Проверь, что выбор сохранён в форме и сообщение о планируемых показах включает нужную страну. Если страна недоступна или кабинет предупреждает об исключении, не включай её в обещанный охват.
5. Проверяй Россию, Украину и другие страны по отдельности. Не переноси ограничения TON на Stars и не считай принятие России разрешением для всего СНГ. Язык канала не доказывает страну пользователя; в Channels не обещай точное гео по одному списку каналов.
6. Запиши в план аккаунт, валюту, режим, URL, выбранные страны, ответ формы и дату. Различай доступность настройки, одобрение модерацией и фактические показы по статистике. При смене аккаунта, режима или посадочной повтори проверку затронутых настроек.
