# Подбирать каналы по продукту и аудитории

## Подключить каталог

Используй `scripts/catalog.py` относительно папки этого навыка. Требуются Python 3, SQLite с FTS5 и pymorphy3. Один раз выполни `python3 scripts/setup_catalog.py`: зависимости установятся в отдельное окружение пользователя. `catalog.py` автоматически использует это окружение, если в текущем Python нет пакета. Скрипт открывает базу только для чтения. Порядок выбора базы: `--db` → переменная `TELEGRAM_ADS_CATALOG` → поле `db` в `~/.config/telegram-ads/catalog.json` → `~/.local/share/telegram-ads/channels.sqlite`. Настройка машины не входит в публичный скилл.

Если базы нет, найди архив TGPages в поставке навыка или по явно указанной ссылке. Скачай все части одного снимка в одну папку, проверь SHA-256 по manifest.json/SHA256SUMS, распакуй `7zz x tgpages-2026-09-14.7z.001`. Не смешивай части разных версий. Сверь SHA-256 channels.sqlite с manifest.json, затем укажи путь к ней. Нет архива или программы распаковки — сообщи конкретно, чего не хватает; продолжай доступное исследование без вымышленных результатов каталога.

Снимок 2026-09-14: 929 981 канал, 66 категорий, 555 микрокатегорий. Названия, описания, usernames, подписчики и категории получены из TGPages. `details_checked_at` означает время чтения источника; актуальность самого Telegram-канала требует проверки. Каталог не содержит достоверной географии подписчиков, цены рекламы, конверсий или измеренного пересечения аудитории.

```sh
python3 scripts/catalog.py stats
python3 scripts/catalog.py search --query 'фотография фотосессия портрет' --match any --limit 40
python3 scripts/catalog.py search --category 'Фотография' --limit 40
python3 scripts/catalog.py similar --seed '@username_из_результата' --limit 30
python3 scripts/catalog.py --format csv search --query 'фотосессия' --limit 50
```

Категории передавай точно как в `stats`; морфологическое расширение русских слов включено по умолчанию. Формы слов объединяются через OR внутри группы, а --match all требует совпадения каждой исходной группы. Это не перевод, не поиск синонимов и не автоматическое добавление смежных тем. Для точного написания используй --exact, для просмотра словоформ — --explain-query (вывод в stderr). Неизвестные словарю названия и латиница сохраняются без склонения. Неоднозначные словарные разборы могут расширять выдачу: релевантность всё равно проверяй по постам. Для UUID используй `id` из результата. Пустая выдача не доказывает отсутствие аудитории: измени слова, проверь категорию и ослабь фильтры. `--min-subscribers` применяй только если он обоснован задачей; размер канала не заменяет релевантность.

## От брифа к поисковым гипотезам

1. Прочитай продукт, оффер, посадочную и имеющийся анализ ЦА. Зафиксируй целевое действие, гео/язык, ограничения и экономику. Если анализа нет — сформулируй рабочие гипотезы и обозначь их как гипотезы. Не приписывай каналу демографию по одному названию.
2. Для каждого сегмента определи ситуацию потребности, ожидаемый результат, барьер покупки и темы, которые человек читает в этой ситуации. Запиши связку: сегмент → потребность → контекст чтения → поисковые слова → подходящий оффер/посадочная.
3. Раздели поиск на прямые темы, смежные ситуации и профессиональные/локальные сообщества. Например, для AI-портретов: фотосессии — прямая тема; личный бренд и поиск работы — гипотезы ситуаций использования. Канал фотографов может собирать поставщиков услуги, а не покупателей: это повод проверить аудиторию, а не автоматически включать площадку.
4. Найди кандидатов через слова в названиях/описаниях и категории. Сохраняй запрос и сегмент, из которого появился кандидат. Список самых больших каналов категории сам по себе не является медиапланом.

## Расширить через сопутствующие каналы

Выбери несколько подтверждённо релевантных исходных каналов (seeds). Для каждого вызови `similar`, прочитай описания соседей и классифицируй их: та же потребность, смежная ситуация, сомнительная связь, нерелевантно. Сохраняй исходный UUID и расстояние как основание обнаружения.

`similar` считает ближайшие точки по евклидову расстоянию на двумерной карте TGPages. Это приближение сходства содержания; оно не воспроизводит внутренний алгоритм рекомендаций сайта и не является графом ссылок или общей аудитории. `audience_overlap=null` означает отсутствие измерения. Не переводить расстояние в процент пересечения, вероятность покупки или прогноз CTR.

Обычно достаточно одного перехода от проверенного seed. Второй переход делай только при нехватке кандидатов, заново проверяя связь с исходной потребностью. Объединяй результаты разных seeds и запросов по UUID, затем по нормализованному username; сохраняй все причины попадания. Не раздувай список повторными соседями. Если доступен инструмент реального пересечения, сохраняй отдельно его источник, дату и определение метрики.

## Проверить и собрать рекламный тест

Для шорт-листа прочитай актуальные публикации, проверь Telegram-ссылку, язык, тематику и соответствие офферу. Географию аудитории и доступность площадки в выбранном типе кабинета подтверждай отдельно. Непроверенное отмечай явно. Ранжируй по соответствию потребности, ситуации покупки, офферу/посадочной и качеству подтверждений; число подписчиков и текстовый ранг — вспомогательные признаки.

Сохрани в проекте заказа таблицу: `id`, `username`, `url`, `segment`, `need`, `query`, `seed_ids`, `discovery`, `category`, `microcategory`, `relevance_reason`, `evidence_urls`, `checked_at`, `geo_status`, `ads_availability`, `confidence`, `decision`, `test_group`. Поле confidence — качественная оценка доказательств с объяснением, не рассчитанная вероятность конверсии. Базу навыка и её архив не изменяй результатами клиентских кампаний.

Группируй тесты по сегменту и гипотезе потребности, отдельно отмечай прямые и смежные площадки. Используй согласованный оффер и посадочную для соответствующего сегмента. Проверяй креативы на фиксированном пуле, затем каналы 1к1 по правилам testing.md; не умножай сразу все найденные каналы на все креативы. Близость каналов не повод автоматически исключать их друг из друга в кабинете. До запуска нужны бюджет, метрика успеха, правило остановки и способ связать площадку с фактическим лидом/продажей.

Результат подбора: обоснованный шорт-лист, отдельные исключения с причинами, непроверенные факты и тестовые группы. Объём списка определяется бюджетом и возможностью проверить гипотезы.

## Проверять качество описаний

Некоторые описания источника содержат служебный текст Telegram (например, Download Telegram / About) или только контакт. Это пропуск содержательного описания: не использовать такой текст как доказательство релевантности. Читай свежие посты. Топонимы дают ложные совпадения (Барселона/Мадрид — также футбольные команды); запросы делай отдельно по смысловым сегментам и исключай спортивные фан-каналы, если оффер с ними не связан. Русскоязычный канал об Испании не доказывает, что все подписчики находятся в Испании.

Для локального запуска ограничивай соседей географическими словами, например `python3 scripts/catalog.py similar --seed emigriceps_spain --query "Испания Испании Валенсия Барселона" --limit 30`. Это фильтр текста, а не геолокация подписчиков. Если свежие публикации показывают переезд канала, смену тематики или подозрительные приглашения, исключи старую площадку до проверки новой.

## Полнота отбора

Для задачи подбора каналов выполняй [полный процесс](channel-selection.md). Все найденные уникальные кандидаты получают статус в реестре; топ-10 для первого теста не заменяет полный список. Лимит CLI — размер выдачи, не критерий завершения исследования.

## Морфология

Используется [pymorphy3](https://github.com/no-plagiarism/pymorphy3), русский словарь, словоформы известных слов. Поддерживается также --query у similar; точные фильтры категорий не склоняются. Перестраивать SQLite и заново скачивать базу не требуется: расширяется запрос к существующему FTS5. Для иностранных языков морфология этим пакетом не настроена.
