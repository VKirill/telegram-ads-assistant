# Отбор, дробление и пересечения каналов

## Собрать пул

1. Опиши людей через потребность, уровень подготовки и ситуацию покупки. «Канал про IT» не означает «новички, которым нужен курс с нуля».
2. Возьми стартовые каналы прямых конкурентов, авторов/экспертов и продуктов для той же аудитории. Добавь смежные потребности отдельными гипотезами.
3. Расширяй через поиск TGStat/Telemetr, упоминания и похожие каналы. В узких и локальных нишах найди конкурентов и профильные организации через поиск сайтов и карты. На их сайтах и карточках организаций проверь ссылки на Telegram; добавляй найденный канал только после проверки содержания, географии и соответствия аудитории. Список похожих — подсказка, не доказательство релевантности или измерение процента пересечения. Семантический подбор Telescope — отдельный способ искать похожий контент, не тот же самый алгоритм.
4. Нормализуй ссылки к одному каналу, убери дубли по ID, если доступен; разные ссылки на один канал не отдельные аудитории. Зафиксируй источник, дату проверки, тематический кластер и основание включения. Просмотри свежие публикации, описание и характер продукта/аудитории, а не только название.
5. Для Target Users оцени число подписчиков как ориентир доступного объёма; для Target Channels — текущий охват/чтение. Не подменяй одно другим. Очень большой канал может смешивать разные аудитории; оцени состав и содержание, не вводи автоматический запрет по числу подписчиков.
6. Проверь доступность канала, язык/гео и явные аномалии роста/контента. Подозрения фиксируй отдельно от доказанного фрода. ERR — отношение среднего числа просмотров публикации к числу подписчиков, выраженное в процентах; период и способ расчёта зависят от сервиса. Низкий ERR не является автоматическим основанием для отказа: он не измеряет потребность аудитории и её конверсию из рекламы. При крайне малом бюджете ERR может быть дополнительным сигналом приоритета, но не универсальным порогом.
7. Раздели пул по объяснимым гипотезам: конкуренты; профильные авторы; смежная задача; широкая тема; отдельное гео. Классификация для организации работы сама по себе не задаёт настройки кабинета.

Результат — таблица каналов с `include / reserve / reject`, причиной решения и режимом таргетинга. Число каналов определяется бюджетом тестов, а не обязательной нормой «500».

## Что значит дробить

Дробление 1к1: 1 объявление = 1 канал при одинаковых креативе, посадочной и остальных условиях. Это позволяет видеть расходы и конверсию каждого тестового объявления и управлять бюджетом отдельно. Групповой тест не показывает вклад каждого канала внутри него.

Если инструмент поддерживает массовое разбиение, загрузи проверенный список и выбери создание отдельного объявления для каждого канала. Названия кнопок, лимит строк и поддержка разбиения проверяются в используемой версии. Без такой функции создавай отдельные черновики по одной строке реестра.

Перед массовым созданием проверь доступные поля и итоговый черновик: количество объявлений, валюту, бюджет **на каждое** и общий бюджет, нужный тип Target, креатив, посадочную, исключения. Сначала проверь одну строку. Без сегментатора можно подготовить импорт или копии по одному, если это допускает инструмент. Не имитируй успешное создание по подготовленной таблице.

Используй отдельный tracking ID на каждую аудиторию/объявление. UTM подходят для сайтов, start-параметры для ботов, поддерживаемые пригласительные ссылки для каналов; произвольные UTM к ссылкам t.me не приписывай. Если инструмент подставляет метки автоматически, проверь итоговый URL каждой строки. При отсутствии такой функции передавай готовые уникальные ссылки, а не нераскрытые шаблоны.

После отбора лучшие можно оставить 1к1 ради контроля или собрать в пул ради управления частотой и масштабирования. В пуле теряется детализация по отдельным каналам; это осознанный компромисс.

## Пересечения: главное различие

| Режим/поле | Что выбирается/исключается |
|---|---|
| Target Users → Target channel audiences | Пользователи, подписанные на целевые каналы; реклама может показываться в других местах |
| Target Users → Exclude channel audiences | Пользователи, подписанные на исключаемые каналы |
| Target Channels → Target specific channels | Каналы как места размещения объявления |
| Target Channels → Exclude specific channels | Места показа, а не все подписчики этих каналов |
| Exclude topics | Смысл зависит от режима; не переноси исключение тематики мест размещения на аудитории |

Поля доступны не во всех кабинетах. Проверь режим и описание поля в реальном UI перед применением. Не обещай произвольный AND/OR или таргетинг только на A∩B без подтверждённой функции.

**Почему нельзя исключать все соседние каналы.** Пусть A — 1 000 подписчиков, B — 800, общих — 300 (учебные, не измеренные числа). Объявление A с исключением B охватит A\B; объявление B с исключением A — B\A. Общие 300 не увидят ни одного из двух. Это не простое удаление повторов: целевой сегмент исчезает.

По умолчанию не исключай каналы тестового пула друг из друга. Исключения вводятся по цели кампании и проверяемой гипотезе, с оценкой потери аудитории.

Практически:

- При привлечении **новых подписчиков** исключи подписчиков рекламируемого канала в Target Users, если поле доступно. При возврате существующей аудитории или продажах ей такое исключение противоречит цели; зафиксируй, что кампания предназначена для существующей аудитории.
- Не считай сумму подписчиков уникальным охватом. Если нет данных о пересечениях, пиши «неизвестно»; по названию/ERR/похожести нельзя получить процент.
- При выгорании проверь вариант единого пула лучших каналов и настройку частоты. Лимит на одно объявление не обязательно является общим лимитом на все объявления/аккаунт — не обещай глобальную дедупликацию.
- Для сравнения стратегии с исключением оставь контроль без исключения; лимитируй бюджет и сравни объём, цену и качество результата. Низкий объём — возможная цена исключений, а не сигнал немедленно повышать CPM.
- Не исключай широкую тематику без сформулированной гипотезы. Интерес к fashion не доказывает пол человека, интерес к криптовалютам не делает его нецелевым инвестором.

Разбиение A и B\A математически сохраняет объединение, но отдаёт общих подписчиков группе A, меняет сравнимость теста и требует проверки поддержки полей. Это отдельный эксперимент по распределению аудитории, а не стандартный способ дробления. Не добавляй такую схему в обычный план без задачи на отдельный эксперимент.
