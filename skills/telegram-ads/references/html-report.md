# HTML-отчёт для человека

После `export_reviews.py` собери страницу штатным скриптом, даже если покрытие неполное: сохраняй все категории и неизвестные результаты.

```sh
python3 "$SKILL_DIR/scripts/render_report.py" --run-dir "$RUN_DIR" --out "$RUN_DIR/final"
```

Входы: `brief.json`, `candidates.json`, `final/reviews.json`, `final/coverage.json`. Выходы: `final/report.html` и `final/report-data.json`. Макет хранится в `assets/report.html`, сборка и фильтры — в `scripts/render_report.py`. Скрипт использует стандартную библиотеку Python; агент не переписывает HTML под каждый запуск.

Повторная сборка из одного JSON:

```sh
python3 "$SKILL_DIR/scripts/render_report.py" --data "$RUN_DIR/final/report-data.json" --out "$RUN_DIR/final"
```

HTML самодостаточен: данные превращаются в строки при сборке, сетевой fetch не нужен, файл работает и без сервера. Одинаковые входные данные и версия шаблона дают одинаковые байты HTML. Изменение JSON требует повторной сборки.

Фильтры категории, стадии и поиска применяются совместно. Под ними показывай выбранные условия; число в категории означает весь её пул, счётчик строк — результат всех фильтров. Кнопка сброса возвращает полный реестр. Сверяй каждую категорию с coverage, не подставляй числа из прошлой версии отчёта.

Для публикации по поручению пользователя переноси только `report.html`, `report-data.json`, `channels.csv`, `manual-ads.csv`, `reviews.json`. Проверь содержимое на приватные сведения перед переносом. Сырые публикации, рабочие пути, авторизацию и назначения агентам не публикуй. HTML не подтверждает готовность канала к размещению: гипотезы аудитории и доступность Ads остаются отдельными проверками.

Порядок строк по умолчанию — число подписчиков по убыванию, неизвестный размер в конце. При равенстве — название и ID. Фильтры сохраняют этот порядок.
