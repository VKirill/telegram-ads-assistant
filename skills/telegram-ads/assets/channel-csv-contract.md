# Итоговая таблица каналов 1.0

Собирай таблицу скриптом `scripts/export_reviews.py`, не переписывай результаты субагентов вручную в CSV. Источник площадок — полный `candidates.json`; результаты анализа — отдельные JSON-объекты или партии по [контракту](channel-review-contract.md). Решения предварительного отсева передай такими же записями `prefiltered/reject` с причиной и `prefilter_source`.

```bash
python3 scripts/export_reviews.py --candidates candidates.json --reviews reviews/batches/ reviews/prefiltered.json selection/size-filtered-reviews.json --out final/
```

Рабочая папка следует [структуре хранения](../references/analysis-storage.md). В `reviews/batches/` должны лежать только результаты анализа, без агрегата предыдущей сборки. Если предварительные отказы уже внутри этой папки, не передавай их второй раз. Исправление оценки заменяет исходную запись после проверки родителем; не добавляй вторую версию с тем же ID.

Скрипт сначала проверяет весь вход. Неизвестный ID, дубли (даже одинаковые), неверный контракт или конфликт останавливают сборку с кодом 1; существующий результат при ошибке проверки не меняется. Отсутствующий результат становится `pending/needs_review`, его ID записывается в `coverage.json:missing_input_review_ids`. Скрипт не придумывает оценки и не отсеивает кандидатов. Код 2 означает сохранённый промежуточный результат; код 0 — все решения завершены по контракту, без гарантии их фактической правильности.

Выход: `reviews.json`, `coverage.json`, `channels.csv` и отдельный `manual-ads.csv` с малыми каналами. Одна строка на каждый уникальный ID из candidates, сортировка по ID, фиксированный порядок колонок. UTF-8 с BOM, разделитель запятая, кавычки по стандарту CSV. Массивы и объекты — JSON внутри ячейки, с сохранением всех ссылок, дат и оснований. null в скалярной ячейке — пусто, внутри JSON остаётся null. Текст с потенциальной формулой получает начальный апостроф; исходное значение остаётся в JSON. Повторный запуск на том же входе даёт одинаковые файлы.

| Колонки по порядку | Источник / смысл |
|---|---|
| id, username, title, url | candidates: идентичность и ссылка |
| subscribers, subscriber_count_checked_at, analysis_route | Число подписчиков, дата снимка, маршрут analyze/manual_ads/unknown_size |
| disposition, category | Машинный класс и подпись: Целевой / Смежный / Для расширения / Отсеян / Требует проверки / Для ручной рекламы |
| status, decision_basis | Стадия и основание: metadata / posts / read_failed / pending / subscriber_count |
| reason, confidence | Причина решения и уверенность |
| observed_topics, audience_hypotheses | Темы и предполагаемая аудитория с основаниями, JSON |
| evidence, prefilter_source | Доказательства по постам либо источник предварительного отсева |
| discovery_sources | Все пути обнаружения из candidates, JSON |
| sample, scores, geo, ads | Полные объекты из review; даты, метод чтения и неизвестные значения сохраняются |

«Отсеян» объединяет reject по метаданным и по постам, но decision_basis позволяет проверить их отдельно. Недоступные и непрочитанные каналы не входят в «Отсеян». Краткий стартовый список формируется отдельно и не сокращает эту таблицу. Родитель проверяет содержание выводов до сборки; валидатор проверяет структуру, а не правдивость доказательств.

Малые каналы всегда видны в общей таблице с category «Для ручной рекламы» и status size_filtered. До сборки архивируй прежние обычные отзывы на них и передай selection/size-filtered-reviews.json, не оба набора. Число подписчиков не равно подтверждённой доступности Ads.
