# Telegram Ads

Методика задаёт, что запускать и по каким правилам останавливать. Приложение записывает это в кабинет Telegram Ads и читает факт. Не заканчивай медиапланом, если просили создать или изменить рекламу. Не трогай кабинет, если просили только план или разбор выгрузки.

## Начало

1. Определи режим: план, подбор каналов, создание объявлений, правка кабинета, чтение статистики или аудит. Для узкого вопроса не начинай весь запуск заново.
2. Извлеки продукт, гео/язык, аудиторию, целевое действие, посадочную, бюджет/валюту/срок, допустимую цену, тип кабинета и уже известные данные. Уточняй только то, без чего нельзя решить.
3. Медиаплан сам по себе не разрешает расход. Если запуск уже поручен с бюджетом и границами, действуй в них без повторного согласования.
4. Нужен кабинет — сразу проверь Assistant по [исполнению](references/assistant-app.md). Есть рабочий MCP — им и создавай, правь, читай. Нет приложения — Computer Use в том же кабинете. Не жди, что пользователь назовёт расширение.
5. Правила: [процесс](references/process.md), [каналы и исключения](references/channels.md), [креативы и лиды](references/creatives-leadgen.md), [тесты](references/testing.md). Шаблоны — [assets/templates.md](assets/templates.md). Пакет объявлений — [пример JSON](assets/assistant-package.example.json). Актуальные лимиты и модерация — [справка платформы](references/sources.md) и текущий кабинет.

В BB-плагине «Агентство» дополнительно прочитай [контекст и артефакты](references/agency.md). Без плагина работай по брифу.

## Каталог каналов

Для анализа посадочного канала и площадок читай публичные страницы `https://t.me/s/<username>` в браузере без авторизации. Не используй личный аккаунт, юзербота, Telegram API/CLI или авторизованный Telegram Web для сбора постов. Порядок чтения и обработки недоступных страниц — в [отборе каналов](references/channel-selection.md). Это правило относится к чтению публикаций; работа в рекламном кабинете следует отдельному маршруту Assistant.

Перед анализом назначь `<папка-запуска>/.agents/<канал-сайт-или-бот>/` по [структуре хранения](references/analysis-storage.md): исходники → пакеты постов → ответы помощников → итоговая сборка.

Обязательный порядок массового отбора: [полный пул, чтение постов, классификация и покрытие](references/channel-selection.md). Итог объединяй скриптом по [контракту CSV](assets/channel-csv-contract.md). Не подменяй полный результат коротким стартовым списком. Профили помощников: [Codex](profiles/codex.md), [Claude Code](profiles/claude-code.md); общие правила и JSON едины.

Для подбора площадок от продукта и анализа ЦА открой [поиск по базе и похожие каналы](references/catalog.md). Сначала найди локальную базу через `scripts/catalog.py stats`, затем используй поиск и расширение от проверенных seeds. Каталог даёт кандидатов; шорт-лист требует проверки содержания, гео и доступности в кабинете.

## Связка «решение → кабинет»

| Задача | Решение по методике | Действие в кабинете |
|---|---|---|
| Новый запуск | Бриф, посадочная, измерение, реестр каналов, матрица тестов | Пакет → validate → prepare → сверка → разрешённый commit → повторное чтение |
| Тест креативов | Один пул, одна переменная — креатив | Отдельное объявление на вариант, одинаковый `target` |
| Тест каналов | 1к1, тот же креатив | `target.channels` из одного username на объявление |
| Пересечения | Не вычитать весь пул из каждой 1к1 | `excludeChannels` только с обоснованием и верным `target.type` |
| Оптимизация | Критерий остановки, журнал до/после | `prepare_edit` / `prepare_budget` → commit → чтение |
| Аудит | Гипотеза vs факт | `read_account`, `read_ad`, `read_statistics` / CSV |

Локальный `id` пакета не равен числовому ID объявления в кабинете. Связь «строка теста → title → externalId» обязательна.

## Обязательная логика

- Сначала цепочка «аудитория → обещание → посадочная → действие» и измерение; потом платный тест.
- Креативы на фиксированном пуле, затем победители на каналах 1к1. Не все каналы × все креативы × все посадки сразу.
- Channels — места показа; Users — аудитории подписчиков. Кампании, анализ и CPM не смешивать.
- 1к1 даёт статистику площадки, не независимые люди. Соседние каналы по умолчанию не исключай.
- Низкий ERR сам по себе не отсекает канал. Итог — релевантность и качество конверсий.
- Нет показов ≠ плохой креатив; мало данных ≠ доказанный провал.
- CTR или дешёвая подписка не равны прибыли. Смотри удержание, качество лида и продажу, если они есть.
- Доступность MCP-команды не разрешает расход. `submitted_needs_verification` не успех. После изменения читай кабинет.

## Результат

Для полного запуска заполни нужные таблицы в проекте заказа и, если просили создание, верни подтверждённые объявления: аккаунт/валюта, local id → externalId, проверенные поля, статус модерации отдельно от активации, бюджет, неизвестное.

Перед завершением: бюджеты сходятся; нет вымышленных пересечений и окупаемости; кабинет не назван проверенным, если работал только с документами; план не выдан вместо создания, если создание было в задаче.
