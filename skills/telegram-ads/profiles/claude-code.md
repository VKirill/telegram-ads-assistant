# Исполнение в Claude Code

Используй общую [методику отбора](../references/channel-selection.md) и [контракт JSON](../assets/channel-review-contract.md). Отличается только запуск помощников; бизнес-правила не дублируются.

Для оценки партий предпочитай доступную в текущем Claude Code модель Haiku. Перед запуском проверь поддерживаемый subagent/Task API, модель и ограничения среды; не используй имя модели как доказательство её доступности. Не переносить параметры reasoning/service tier Codex в Claude. Если Haiku или субагенты недоступны, основной агент обрабатывает те же партии по общему контракту, сообщив фактический режим.

Каждому помощнику передай brief.json, IDs партии (обычно 10–20), конкретные файлы постов, общий контракт и отдельный путь reviews/batches/batch-NNN.json. Поручение: оценить все назначенные IDs, разделить наблюдения/гипотезы, сохранить ссылки, при нехватке данных вернуть needs_review. Запретить изменение брифа, запуск рекламы, отправку сообщений и самостоятельное расширение привилегий. Не давать секреты и весь чат.

Посты читай только на публичных страницах `t.me/s/<username>` через браузер без авторизации, по общей методике. Не используй юзербота или пользовательскую Telegram-сессию. Параллельно анализировать уже извлечённые файлы можно в пределах лимитов среды. Родитель объединяет партии, проверяет доказательства и покрытие всех candidates, возвращает спорные случаи на проверку. Итог с неизвестными статусами остаётся промежуточным.

Пути входов и результатов задавай относительно RUN_DIR по [структуре хранения](../references/analysis-storage.md); помощник пишет только назначенные ему файлы.
